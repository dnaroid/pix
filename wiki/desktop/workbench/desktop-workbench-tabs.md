# Desktop unified workbench tabs

<!-- markdownlint-disable MD013 -->

## Type

Change

## Lifecycle

Active implemented contract.

## Goal

Present conversations, file/media Preview, Source Control Git Diff, interactive Terminal, and transient workbench-owned utility surfaces such as LSP installation as sibling tabs in one titlebar workbench strip while preserving the existing runtime/session lifecycle separately from workspace-only UI surfaces.

## Behavior

- Pix Desktop has one top `WorkbenchTabs` tablist. There is no second nested editor-tab strip inside the central workspace.
- Conversation tabs are derived from the existing `buildTabSessions` order plus the UI-only draft conversation. Their session membership, restart restore, Desktop/TUI reconciliation, and active-session persistence follow [desktop-session-tabs.md](../conversations/desktop-session-tabs.md); the unified workbench layer does not give Preview, Git Diff, Terminal, or LSP installer tabs any role in that state. Runtime ownership and ACP close semantics remain session-owned.
- Preview, Git Diff, Terminal, and the LSP installer are UI-only workbench tabs. They never enter `buildTabSessions`, restored/local session id arrays, saved-session selectors, active-session persistence, ACP session maps, or TUI `pix.tabs` metadata.
- UI-only workbench tabs are inserted beside the visible tab that opened them when possible while the relative order of the canonical session list remains authoritative. If the opener disappears, the UI-only tab remains workspace-scoped and falls back to a valid location in the same strip.
- A tab's context menu additionally offers **Move Tab** when there is more than one tab and the target is not mutation-disabled. This explicitly picks up the tab: moving the pointer previews an insertion marker; clicking inside the tab strip places it. Left/Right and Home/End choose a position, Enter/Space places, and Escape cancels; move-mode status announces the target position. Tab, an outside pointer press, a new context menu, window blur, pointer cancellation, source/target removal, disabling the source, workspace change, or unmount cancels without moving tabs. The picked-up tab stays selected/unselected as before; placement does not activate or close another tab. After placement, focus returns to the keyed tab element after the UI update, unless the workspace changed, the component unmounted, or another action took focus.
- Explicit reordering overrides only this window's visible workbench order for the current workspace lifetime; it does not change canonical session membership/order, ACP/TUI state, or restart persistence. Newly opened tabs still insert beside their canonical neighbor; closed ids are pruned. Switching workspace or restarting resets the visual override. Session, draft, Preview, Diff, Terminal, and installer tabs share this behavior.
- Outside this explicit move mode, dragging a tab, its close control, New Conversation, or free titlebar space still moves the native window. During move mode only pointer gestures inside the tab strip are intercepted; an outside press cancels and remains available to the original control/window drag behavior.
- Exactly one workbench tab is visually/ARIA selected. Selecting a session tab activates/loads that conversation and displays `conversation-workspace`. Selecting Preview, Git Diff, Terminal, or LSP installer changes only the visible central work surface; the active conversation runtime remains available in the background.
- Opening a bounded project/home/absolute UTF-8 text file or supported media creates/updates the single Preview tab and selects it. Interactive non-media files over 256 KiB or 2,000 source lines open in the configured external editor without creating/selecting Preview or adding history; missing editor configuration prompts Desktop Settings. Absolute local directories and small binary/non-UTF-8 files retain the system-opener fallback. Preview retains its existing browser-like back/forward history instead of opening one tab per followed link. See [desktop-markdown-rendering.md](../rendering/desktop-markdown-rendering.md) for the bounded-read and editor-launch contract.
- Opening Source Control diff/review creates/updates the single Git Diff tab and selects it. Opening a file reference from Git Diff selects Preview while Git Diff remains open.
- Local `.glb` files route through approved media resolution rather than text
  reads and open in Preview's shared interactive model viewer. Project, absolute,
  home-relative paths and prepared file attachments are supported. The viewer
  provides free rotation, middle-button panning, zoom, and camera reset with
  the same 64 MiB embedded-only GLB 2.0 policy and
  lifecycle ownership as [Markdown model previews](../rendering/desktop-markdown-rendering.md).
- Image and video Preview fit the bounded media viewport with preserved aspect
  ratio and no cropping, scaling up beyond intrinsic dimensions as needed; neither
  is capped to the chat-column width. Audio and GLB presentation are unchanged.
- Conversation, Preview, and Git Diff remain mounted while merely hidden by another workbench tab so composer/transcript state, Preview edit draft/history/scroll, media state, and Git review output do not reset on ordinary tab switching.
- Switching to a different conversation selects that session's workbench tab but does not discard workspace-scoped Preview or Git Diff tabs. Their state remains available until explicitly closed or the workspace lifecycle invalidates it.
- Preview shows a dirty indicator while its editable project-text draft differs from the loaded file. Any existing UTF-8 project file that is small enough to open in Preview can enter edit mode; home-file and absolute local-file previews remain read-only. Closing dirty Preview asks before discard; cancellation keeps the tab/state intact. Workspace changes and project-reloading Git mutations keep the existing dirty-preview confirmation.
- Markdown editing defaults to **Visual**, with a **Source** mode retaining the
  textarea. Both share the same draft and save lifecycle; line-range previews
  start in Source. See [Project Wiki](desktop-project-wiki.md) for the editor and
  authored relative-link contract. A new Preview target or history move cannot
  replace an unsaved draft; Save or Cancel resolves it first. Ordinary file saves
  compare loaded content with disk immediately before replacement and refuse
  observed external changes.
- Every Preview surface of a real file or attachment provides a separate **Copy file** toolbar action (generated Wiki folder contents have no on-disk file and show no Copy file; see [Project Wiki](desktop-project-wiki.md)), using the native file-copy action to copy the on-disk file rather than rendered content or an unsaved draft. This applies to text, image, audio, GLB, and video previews; workspace-relative text paths resolve against the workspace, while absolute and home-relative paths are retained. The action is disabled when no usable local path is available (for example, an embedded image without a file path). Video has one **Copy file** button, not a duplicate media-copy button.
- Text Preview also provides **Copy contents**, which copies the full raw file content (including Markdown source rather than rendered text), or the current unsaved draft while editing. Image Preview retains **Copy image**, which copies image pixels using the approved image-copy path. Text copy uses Tauri's native clipboard in the Desktop app and the browser clipboard otherwise. Copy actions expose accessible status feedback, show a success icon after copying, and log failures.
- Preview close confirmation is single-flight: repeated close attempts while an asynchronous dialog is pending neither open a second dialog nor invoke close twice. A cancellation leaves the same draft visible; a late confirmation must not close a replacement Preview.
- Right-clicking the Preview tab header offers Copy File, Open in External App,
  and Reveal in Finder for the current entry's underlying local file, including
  while the tab is inactive. See [context menus](desktop-context-menus.md) for
  file clipboard semantics and content/media routing.
- File reads and attachment preparation share Preview load ownership. Closing, navigating, opening an immediate preview, or invalidating the workspace prevents an older load from replacing/reopening the current Preview or reporting an obsolete error.
- Project-text saves capture their workspace and originating Preview entry. Ordinary files use the workspace-confined existing-file writer, while legacy TODO and plan Markdown retain their specialized project-document writer for read/edit compatibility; only canonical plan Markdown participates in Registry sync. Writes to the same workspace/path are serialized; a late save cannot replace a reopened entry with the same path, unlock another edit's save, or close a newer edit. Text typed while saving remains an editable dirty draft rather than being replaced by the saved snapshot.
- A Preview file surface exposes `Find in file` and intercepts `Ctrl+F` / `Cmd+F` only while the Preview tab is active. The find widget searches the current rendered text in read-only or visual Markdown Preview, or the live source draft in textarea mode, uses literal ASCII-case-insensitive matching, reports the current/total match count, and navigates forward with Enter or backward with Shift+Enter. Rendered matches use non-destructive CSS highlights with the active hit distinguished; source editing uses textarea selection/scrolling. Typing in the find field searches after a 100 ms pause (Enter searches immediately); Enter/Shift+Enter reuse the current matches instead of searching again. Only a query change or explicit navigation moves the textarea selection or scrolls to the active match: edits to the source draft while find is open only recount matches and never move the caret. Rendered text is collected once per DOM change (tracked by a mutation observer released on close/unmount), and match ranges are located by binary search. Clearing the query, closing find, opening a different Preview history entry, or unmounting Preview immediately removes every search-created CSS highlight, fallback DOM selection, and textarea selection without clearing a newer manual user selection.
- Git Diff shows a compact busy indicator during LLM review/resolve work without becoming a modal.
- The Terminal tab is a closable UI-only workbench surface backed by the existing window/workspace PTY sessions. Composer `!!` opens or reuses this tab and starts a new shell command there. Closing the workbench tab removes only that surface; terminal-level Close/Stop controls own process teardown.
- The LSP installer is another UI-only auxiliary workbench tab: it never enters session persistence or ACP/TUI tab metadata, is anchored next to the conversation that requested it, and selecting it leaves that conversation as the underlying runtime.
- The LSP installer is non-closable while installation is active and becomes closable on success/error. Closing it removes only that installer surface.
- The unified tablist uses roving focus: Left/Right and Home/End move focus without activation, Enter/Space activate via native button behavior, Delete closes a closable focused tab, and middle-click uses the same close path.
- Closing Preview, Git Diff, Terminal, or a completed LSP installer removes only that UI surface. Closing a session uses the existing session-close flow, including running-session confirmation and ACP teardown. When an active session closes next to an auxiliary tab, Pix may keep the necessary fallback session runtime active underneath while selecting the logical neighboring workbench tab.
- A sole UI-only draft conversation remains non-closable. New Conversation remains the one trailing action outside the roving tab sequence. The tablist/action group shrink-wraps their contents; the tablist may shrink and scroll horizontally in a narrow titlebar, while New Conversation is fixed immediately after the last visible tab and unused space remains the drag region. Each tab's preferred width matches its flex basis (200px, or 180px below the 760px breakpoint), may shrink to 120px, and has no larger intrinsic maximum.
- Session-kind tabs keep their semantic session-status icon even while an auxiliary workbench tab is selected. Status and workbench selection are independent: the icon reports session execution/attention/completion state while the tab border/background remains the only selected-surface affordance.
- A real session tab whose ACP session metadata marks it as a fork shows a compact branch icon before its title, alongside (not instead of) the session status icon. Draft, Preview, and Git Diff tabs never show this fork marker.
- The saved-session selector and embedded draft selector remain session-only. UI-only workbench tabs never appear as resumable conversations.
- Command Palette entries **Show Conversation**, **Show Preview**, **Show Git Diff**, and **Close Active Editor** target this unified workbench model. Focus Composer first selects the active conversation tab before focusing the hidden/mounted composer.

## Non-goals

- Persisting Preview, Git Diff, Terminal, or LSP installer tabs across application restarts.
- Treating Preview/Git Diff/Terminal/LSP installer surfaces as ACP sessions or TUI tabs.
- Opening multiple independent Preview tabs; Preview keeps one history-bearing work surface.
- Converting bounded settings, elicitation, or model-selection flows into workbench tabs.
