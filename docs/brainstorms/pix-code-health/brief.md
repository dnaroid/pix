## Known evidence (parent inspected current local working tree, installed SDK 1.1.0; test SOURCES read, tests NOT run)
1. Heads Up active contract explicitly excludes code review/enforcement. Opt-in passive conversation/tool-evidence observer, max three active cards, no autonomous file reads, tool-less registry inference with no child sessions/tools/retries/fallback. It does not inject to or resume parent. Successful final settlement controls automatic inference; strict conversation-evidence invalidation, per-runtime budgets/history, physical transport lock retained if cancellation ignored. Relevant decision 0034 is accepted opt-in experiment, with follow-ups; read current spec rather than extrapolating old decision.
2. SDK 1.1.0 agent_settled means fully settled after retries/compaction/queued continuations, but event has aborted only, not full success outcome. Observer tracks final agent_before_settle.outcome (completed versus failed). turn_end is not sufficient. Nested ctx.executeTool/codemode calls emit tool_call/tool_result/tool_execution_* with parentToolCallId and keep bounded nestedCalls on parent instead of separate transcript results. This is a better mutation source than parsing codemode prose, but not coverage for child processes/shell/external writers.
3. SDK runner awaits tool_result handlers sequentially; adding async analysis there is critical-path latency. Changing content without replacing structuredContent drops structuredContent. Existing LSP and comment-checker enrich hook results; they are not a nonblocking background pipeline.
4. lsp/mutation-events getEventPaths prioritizes nonempty details.changedFiles, otherwise path/file_path/paths and Begin Patch Add/Update/Delete/Move headers; trims/dedups string paths. isMutationToolResult handles qualified write/edit/apply_patch, ast_apply with changedFiles, patch-shaped input. These are candidate paths, not comprehensive observed FS mutation proof. Generic shell/external writes not captured. lsp lib skips errors and filters existsSync, hence deletes are not diagnosed. Failed tools can still partially mutate: a future tracker cannot equate isError with unchanged filesystem.
5. comment-checker extracts added comments from write/edit/multiedit/apply_patch; ast_apply skipped without cheap diff. Resolves approximate line anchors by reading postwrite files. lastNudgeTimestamp is module-scoped although comment says per-session: do not blindly copy its dedup ownership.
6. Existing LSP has trusted project-execution config flow, lazy startup, canonical physical-root identity, POSIX project broker and owner leases; different real language workspaces stay distinct, Windows TUI fallback is local. Last owner closes; 15min idle measured from operation completion; monitoring never starts servers or prompts trust. sharedDiagnosticsForFile returns Promise<string>, not public versioned structured Findings. Do not promise direct reuse as a structured store or fully sandboxed lint execution.
7. Existing AST-grep suite module invokes external ast-grep executable through pi.exec (120s tool timeout). This is an available integration, not a guaranteed installed runtime parser library. TypeScript is a devDependency; don't assume portable runtime compiler availability without packaging analysis. Desktop Svelte checking exists but doesn't solve generic suite-language coverage.
8. Disposable task output belongs under unique .pi/artifacts/, harness subagents/QA under .pi/subagents/. Initialized Desktop background cleanup TTL72h and manual cleanup immediate: durable baselines/suppressions must not live in scratch.
